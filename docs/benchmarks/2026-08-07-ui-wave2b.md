## 1. The height budget, closed as far as it honestly goes

| | before wave 2a | after 2a | after 2b |
|---|---|---|---|
| drop zone | 116 | 116 | **40** (intake chip) |
| analysis card | 200 | 200 | **99** |
| chooser | 401 | 401 | **236** |
| queue + results | ~230 | 0 (own tab) | 0 |
| **populated page** | **869** | **748** | **415** |
| **empty page @150 %** | overflows | overflows by 35px | **fits, 0px scroll** |

Populated page **869 → 415px, −52 %**. The empty Compress page fits a
150 %-scaled 1366×768 display for the first time in the project's history —
that gate was a strict xfail at the end of wave 2a and now passes, so it has
been promoted into the parametrized regression gate.

### Why the populated page stops at 415 and not §2.4's 300

Every item is already at its compacted size:

```
intake chip                 40   32px touch floor + 2px border + margins
analysis card               99   headline + bar + gain note; rest behind Details
chooser                    236   of which 4 profile rows are 168
page margins + 2 gaps       40
                         -----
                           415
```

Closing the last 115px needs one of three things the product has decided to
keep:

1. **Fewer than four profile rows** (−84px). Comparing all four *is* the
   chooser; W1-13 merged two widgets precisely so one table shows them.
2. **Collapsing the analysis card** (−99px). That card is why the app exists.
3. **Rows below 32px.** W2-4 has just adopted the Windows touch floor
   ("32 epx tall if the width is at least 120 epx") in the same wave.

**research/23 §2.4 and §3.3 cannot both hold.** §2.4's arithmetic budgeted
4×32px rows *plus* 44px of chooser chrome at 172px total, but four 32px rows
alone are 128px, leaving 44px for a title row, a column header, margins and
gaps. The ≤300px assertion stays in the suite as a `strict=True` xfail so
re-opening it is a deliberate decision, not an oversight.

### Rows: where the 32px floor holds, and where it honestly cannot

| row | height | why |
|---|---|---|
| Fast | 34 | single-number estimate |
| Normal | 34 | single-number estimate |
| Extreme | 51 | cells carry a **range** — Precomp's gain is unknowable until it runs |
| Insane | 51 | same |

Inlining the range (`≤ 8.5 MB (6.0 MB – 16.6 MB)`) needs ~210px in a 178px
column, so it clips; hiding it is the false precision this app exists to
refuse. The extra 17px sits exactly where the uncertainty is.

## 2. What the compaction cost, and what it did not

Nothing honest was demoted to a tooltip:

- **gain note** — permanently visible; never collapsible.
- **breakdown bar** — the swatch legend moved into Details, which is only safe
  because the headline states the same shares in words ("86 % game/app data ·
  8 % video · 4 % text"). Pinned by a test.
- **missing-tool caveat** — now *elided* with "…" instead of hard-clipped
  mid-word ("zpaqfranz missing — runs as E:"), with the full sentence in the
  tooltip and the spoken name.
- **estimator footnote** — behind the ⓘ disclosure W1-13 specified and never
  built. A real focusable button, not a tooltip.

### A real accessibility bug the elision test surfaced

`ProfileRow` appended `row.caveat` to its accessible sentence **only in
placeholder mode**. The moment estimates arrived, a screen-reader user stopped
being told that Insane silently degrades to Extreme because zpaqfranz is
missing — which is the only thing that caveat exists to say. Fixed; the caveat
is now always spoken.

## 3. W2-5: icons

Four glyphs vendored from **Fluent UI System Icons** (MIT,
`assets/icons/` with the upstream `LICENSE` beside them — the OSI-clean rule
is a hard repo constraint for SignPath):

| profile | was | now |
|---|---|---|
| Fast | ⚡ | `flash` |
| Normal | ⚖️ | `scales` |
| Extreme | 🔥 | `fire` |
| Insane | 🌙 | `moon` |

`gui/icons.py` string-substitutes the SVG `fill` with a theme token before
rendering, so the glyphs **recolour on theme toggle** — the thing an emoji
could never do, being a colour bitmap. First render used `$muted` and produced
three near-invisible ghosts beside one green flame on `$surface`; they use
`$text` now, with `$ok` for the recommended row.

The emoji stay in `PRESETS` as text fallbacks; nothing paints them any more.

## 6. The QA pass that should have happened first

Wave 2b was reviewed by looking at three dark-mode screenshots. That is not QA.
A proper sweep — **12 surfaces × both themes**, including the ones no test and
no README shot had ever rendered (the banner, the Extract tab, the expanded
pending list, a failed-job results panel, the Advanced panel, the About card,
everything-disclosed-at-once) — found two defects that 371 passing tests did
not:

1. **"100% or better".** A Precomp ceiling of 1.5 KB out of 371.5 KB is 99.6 %,
   which `fmt_percent` rounds to 100 — so the chooser advertised a saving of
   100 % or *more*, i.e. an archive of zero bytes or smaller. From an app whose
   entire identity is refusing to overpromise, this was the worst sentence on
   screen. `gui.suggest._saved_words` now caps the **wording** at 99 % while
   leaving the estimator's own number untouched, so nothing downstream is lied
   to. Pinned by `test_a_saving_is_never_advertised_as_100_percent`.
2. **The pending list was a fixed 120px box** holding three short filenames —
   most of a chip's worth of empty grey, in a panel disclosed on demand. It
   sizes to its rows now, capped at six.

Light mode itself came through clean: radii consistent, tinted SVGs legible on
white, the banner readable, WCAG tokens holding. But that was luck, not
verification — W2-4 changed every radius and W2-5 added theme-tinted icons, and
neither had been looked at in light mode before this sweep.

**Lesson worth keeping: automated tests pin behaviour, not appearance.** Every
visual defect this wave produced — the fat progress bars, the invisible muted
glyphs, the mid-word clip, and both of the above — was found by rendering a
surface and looking at it. It ships as `tools/qa_sweep.py`; run it
before calling a UI wave done.
